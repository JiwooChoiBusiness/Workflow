# ADR-0002: 개인용으로 재정의, GitHub은 코드 보존용

- 상태: 채택
- 날짜: 2026-10-12
- 대체: ADR-0001의 D1(타깃 사용자), D2(배포 모델)를 아래 내용으로 바꾼다. D3(기능 복제), D4(의존성 원칙), D5(단계 순서)는 그대로 유지한다.

## 결정

### D1'. 사용자는 본인 1명
- 이 플랫폼은 작성자 본인 혼자 사용한다. 멤버 초대, 역할, 권한 구분, 감사 로그 같은 다인 사용 기능은 만들지 않는다.
- 계정은 초기 설정에서 만드는 로컬 계정 1개다. 로그인은 유지한다. 브라우저에 열린 포트를 다른 프로그램이 호출하는 것을 막는 최소 장치다.
- 모든 핵심 테이블의 workspace_id는 유지한다. 비용이 거의 없고 나중에 다인 사용으로 넓힐 여지를 남긴다.

### D2'. 로컬 우선 배포
- 기본 실행 환경은 본인 PC(Windows 11 + Docker Desktop, WSL2 백엔드)다. docker compose 한 벌로 띄운다.
- gateway는 127.0.0.1에만 바인드한다. TLS, 외부 노출, 고가용성은 범위 밖이다. 개인 Linux VM에 올리는 것은 선택 사항으로 두고 같은 compose를 쓴다.
- 샌드박스 격리는 그대로 유지한다. 위협 모델이 바뀌기 때문이다. 다른 사용자가 아니라 모델이 실행하는 코드, 모델이 읽는 웹 콘텐츠와 파일, 설치되는 패키지가 신뢰할 수 없는 대상이다. 사용자는 신뢰한다.
- 기본 자원은 개인 PC 기준으로 줄인다. 동시 샌드박스 3개, 동시 런 3개.

### D3'. GitHub은 코드 보존용
- 비공개 저장소에 소스 코드와 문서만 푸시한다. 데이터, 스냅샷, 업로드 파일, .env와 비밀값은 저장소에 넣지 않는다.
- CI는 린트와 테스트까지만 둔다. 이미지 레지스트리 푸시와 배포 자동화는 만들지 않는다.
- 데이터 백업은 로컬 스크립트(pg_dump + storage 볼륨 tar)로 하고 GitHub과 분리한다.

## 영향
- docs/design/phase1-agent-sandbox.md에서 초대·멤버·역할·감사 로그·엔드유저 관련 항목을 제거하거나 단순화한다.
- ADR-0001의 미결 질문 중 웹앱 접근 범위(본인만), 초대 메일(불필요), 저장소 공개 여부(비공개)는 해결된다.
