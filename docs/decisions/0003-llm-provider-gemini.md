# ADR-0003: LLM 프로바이더는 Gemini, 키 로테이션과 모델 폴백

- 상태: 채택 (Anthropic 어댑터 유지 항목은 ADR-0004로 폐기, Gemini만 사용)
- 날짜: 2026-10-12
- 배경: 사용자가 Gemini API 키 8개를 제공했고, 3.8 Flash → 3.7 Flash → 3.6 Flash 순서로 쓰라고 했다. 2026-10-12 호출 테스트에서 키 8개 모두 유효했고 세 모델이 모델 목록에 있었다. 테스트 시점에 3.8과 3.7은 503(수요 폭주)을 돌려줬고 3.6은 정상 응답과 도구 호출(function calling)까지 동작했다.

## 결정
- 1단계의 기본 LLM 프로바이더는 Gemini다. 호출은 Gemini의 OpenAI 호환 엔드포인트(`/v1beta/openai`)로 하므로 설계의 OpenAI 호환 어댑터가 그대로 쓰인다. 별도 Gemini 전용 어댑터는 만들지 않는다.
- 모델 폴백: 요청은 `gemini-3.8-flash`부터 시도하고, 429·503 같은 일시 오류면 `gemini-3.7-flash`, 그다음 `gemini-3.6-flash`로 넘어간다. 400·401 같은 요청 오류는 폴백하지 않는다. 폴백 순서는 `.env`의 `GEMINI_MODEL_FALLBACK`에 둔다.
- 키 로테이션: `GEMINI_API_KEYS`에 쉼표로 나열한 키를 순서대로 돌려쓴다. 어떤 키가 429를 받으면 다음 키로 넘어가고, 모든 키가 429면 모델 폴백으로 간다.
- 키는 `.env`에만 둔다. 저장소, 문서, 로그, 채팅 보고에 키 값을 쓰지 않는다.
- Anthropic 어댑터는 설계대로 유지하되 키가 없으면 비활성이다.

## 영향
- 설계 4.3의 OpenAI 호환 어댑터에 "여러 키 로테이션"과 "모델 폴백 목록" 기능이 추가된다. M4에서 구현한다.
- 모델 능력표(`app/llm/catalog.py`)에 Gemini 3.6/3.7/3.8 Flash 항목을 넣는다. 컨텍스트 창과 출력 상한은 M4에서 API 응답으로 확인해 채운다.
- 테스트에서 3.6 Flash가 `max_tokens`가 작을 때 사고(thinking) 토큰에 예산을 다 써서 빈 응답을 돌려줬다. 어댑터는 출력 상한을 넉넉히 잡고, 빈 응답이면 상한을 올려 1회 재시도한다.
